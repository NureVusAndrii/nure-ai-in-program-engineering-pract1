# Mini Issue Tracker — UX/UI specification and clickable prototype

**Практична робота «AI у програмній інженерії: від специфікації до перевіреного UX/UI-макета».**

**Макет:** [Figma — робоча версія](https://www.figma.com/design/BlBanabnVhdnqtKHHZa8qg/Untitled?node-id=0-1) · **Джерело:** `00_sources/SD_Spec.docx` · **Методика:** `00_sources/Methodological_Guide.docx`.

**Відеозахист:** `посилання з'явиться пізніше`.

## Мета та результат

Виконано документальну підготовку низькодеталізованого UX/UI-прототипу внутрішнього вебтрекера проблем для невеликої команди: створення, перегляд, призначення, пріоритет, статус, коментарі, важливі незакриті заявки. Release MVP — **US-01–US-08**; US-09 (вкладення) перенесено; SR-10/SR-11 (AI-рекомендації) відкладено. Це **макет та специфікація інтерфейсу, не реалізований вебзастосунок**.

## Контрольні бізнес-правила

- Тільки **Team Lead** призначає одного виконавця та встановлює/змінює Priority.
- **Status** змінює тільки поточний **assignee**, навіть якщо інший користувач — Team Lead.
- Дозволено рівно `Open → In Progress`, `In Progress → Resolved`, `Resolved → In Progress`, `Resolved → Closed`.
- `Important = (Priority ∈ {High, Critical}) AND (Status != Closed)`; `Resolved` залишається активним, `Not Set` не дорівнює `Normal`.
- У Create користувач вводить тільки Title і Description; порожні поля дають відповідні помилки; початкові значення — Open та Not Set.
- Видалення, історія змін, вкладення й AI-рекомендації не входять до цього UX/UI MVP.

## Короткий маршрут демонстрації

All Issues → Important Issues → All Issues → New Issue (overlay) → помилки для порожніх Title/Description → заповнення обох полів → Create → prepared issue details → Back. Окремо: Cancel повертає на попередній список; role/status/comment/error/empty states показуються як reference examples. Подробиці — [`Prototype_Test_Record.md`](04_quality_assurance/Prototype_Test_Record.md).

## Рівні перевірки

- **SOURCE CHECKED:** вихідні ID/текст/правила звірено з SD_Spec та методикою.
- **DOCUMENT REVIEW:** перевірено наявність вимоги в документації/контракті; це не підтвердження макета.
- **USER REPORTED:** незалежним записом перевірено, що переходи працюють.
- **NOT INDEPENDENTLY VERIFIED:** вміст поточної онлайн-Figma/роботу Present не підтверджено доступним інструментом.
- **IMPLEMENTATION ONLY:** справжня автентифікація, авторизація на сервері, збереження даних, HTTPS, резервне копіювання та швидкодія.
- **PASS:** усі попередні пункти виконані, перевірені кожним членом групи та захищені.
