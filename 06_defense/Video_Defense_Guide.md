# Відеозахист — сценарій та контрольний маршрут

За методичкою §22 для заочного захисту рекомендовано командне відео, де кожен учасник демонструє власний внесок і контрольний випадок. Скриншоти у GitHub не є безумовно обов'язковими, але відео та Figma повинні давати **читабельні докази**.

## Послідовність запису

1. **30 с:** учасники `[ІМЕНА]`, вихідна SD_Spec, Figma URL, розподіл роботи.
2. **1–1,5 хв:** відкрити Figma Present: All → Important → All → Create overlay → обидві required errors → по черзі заповнити поля → Create → new issue Details → Back. Пояснити, що це симуляція.
3. **30 с кожен:** особистий внесок: Source Check/Traceability; Contracts/Decision Log; Figma/Prototype; QA/Defect Log (розподіл лише фактичний).
4. **30–60 с кожен:** показати одну вимогу в SD_Spec → її UIR-ID у CSV → control/state у Figma → T-ID у протоколі.
5. **1–1,5 хв кожен:** різні контрольні кейси: Lead non-assignee cannot change status; Resolved+High included in Important; Closed terminal; comment save failure; empty list.
6. **30–60 с:** показати Defect/Change Log, що виправлено, що лишається неперевіреним; розмежувати UI, SIM, IMPL.

## Як зробити відео доказом

- У кадрі має бути **реальна** Figma та видимі кліки, не тільки статична презентація.
- Збільшити масштаб так, щоб читалися поля й error labels.
- Назвати версію Figma та дату тесту.
- Записати timecodes для T-01..T-10 у `../04_quality_assurance/Prototype_Test_Record.md`.
- Якщо сценарій не вдалося пройти, зафіксувати FAIL, виправлення та повторну перевірку.
- Для відео з кількома учасниками не приписувати одному роботу іншого.
